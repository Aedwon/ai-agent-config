# Content-Heavy Project Overlay

Baseline: `software-project.md` when the project includes executable tooling;
otherwise apply this overlay directly after project rules.

- Record source, author, license, revision or access date, and transformation
  history for material that requires provenance.
- Validate content independently from code. Passing software tests does not
  establish factual, editorial, legal, or policy correctness.
- Define content schemas and reject incomplete records at ingestion.
- Require the appropriate editorial or subject-matter review before publication.
- Never fabricate facts, citations, quotations, permissions, approvals, or
  review results.
- Preserve original material when transformations must remain auditable.
